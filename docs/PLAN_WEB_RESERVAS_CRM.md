# Plan técnico — Web, reservas y CRM

## Objetivo
Convertir la web en un sistema confiable para presentar alojamiento y experiencias, mostrar disponibilidad, explicar condiciones de reserva y facilitar el seguimiento comercial.

## Flujo mínimo
1. El visitante entiende qué puede reservar.
2. La disponibilidad mostrada es coherente.
3. La reserva llega a un proceso claro.
4. El anticipo o pago se explica antes de confirmar.
5. El contacto entra a un seguimiento ordenado.
6. El equipo recibe información suficiente para operar.

## Fases

### 1. Estabilización
- revisar páginas, navegación y contenido;
- ocultar páginas incompletas;
- verificar formularios y enlaces;
- documentar configuraciones sin incluir credenciales.

### 2. Reservas
- definir habitaciones y experiencias;
- estandarizar disponibilidad, horarios y cupos;
- documentar políticas de confirmación, cancelación y reprogramación;
- probar el recorrido completo como visitante.

### 3. Seguimiento
- definir qué datos mínimos se capturan;
- evitar duplicación entre herramientas;
- asignar responsable y estado a cada solicitud;
- proteger información personal.

### 4. Operación
- convertir reservas confirmadas en tareas operativas;
- usar listas de preparación y cierre;
- documentar mantenimiento y contingencias;
- separar información técnica de datos de huéspedes.

## Criterios
- herramientas simples y sostenibles;
- privacidad por defecto;
- ningún secreto en GitHub;
- cambios probados antes de publicarse;
- documentación actualizada.
